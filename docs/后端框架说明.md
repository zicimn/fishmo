## 1. 项目概览

### 1.1 项目定位

`fishmo` 是一个基于 **FastAPI** 的纯后端项目（目前尚无前端，CORS 已为前端预留）。项目围绕**用户体系**展开，当前已具备注册 / 登录 / 更新 / 删除、JWT 鉴权、邮箱验证码（Resend + Redis）等能力，并预置了「版本化缓存失效」模式的缓存基础设施，为后续列表 / 搜索类接口预留了缓存升级空间。

### 1.2 技术栈

| 领域 | 技术选型 | 版本 |
| --- | --- | --- |
| 语言 | Python | 3.11+ |
| Web 框架 | FastAPI | 0.133.1 |
| ASGI 服务器 | Uvicorn | 0.41.0 |
| ORM | SQLAlchemy（异步） | 2.0.47 |
| MySQL 驱动 | aiomysql | 0.3.2 |
| 数据校验 | Pydantic | 2.12.5（v2） |
| 密码哈希 | passlib + argon2-cffi | passlib 1.7.4 |
| JWT | python-jose | 3.5.0 |
| 缓存 / 验证码存储 | redis.asyncio | 7.3.0 |
| 邮件发送 | resend（SDK） | 2.35.0（**未写入 requirements**，见[已知注意事项](#10-已知注意事项)） |
| 环境变量 | python-dotenv | 1.2.1 |

### 1.3 当前功能清单

- 用户注册（含邮箱验证码校验、唯一性约束）
- 用户登录（argon2 校验 + 签发 JWT）
- 用户信息更新（用户名 / 邮箱 / 简介 / 头像 / 密码，含排重）
- 用户删除（软删除未做，为物理删除）
- 邮箱验证码发送与校验（Redis 存储、5 分钟有效、一次性使用）
- 基于 `HTTPBearer` 的 Token 鉴权（`verify_login` 工具）
- Redis 缓存工具集与版本化失效模式

注意一个结构细节：`api/` 目录本身**没有** `__init__.py`，依赖 Python 3 的命名空间包机制工作；只有 `api/v1/` 是常规包（含 `__init__.py`）。

### 2.2 分层与导入约定

- **分层设计**：规划方向是 `router → service → repository` 的领域分层，但目前业务逻辑仍直接写在 `api/v1/user.py` 路由内（登录、注册、排重、哈希均内联），尚未抽出 service / repository 层。`utils/` 承担了少量跨路由复用逻辑（鉴权、邮件）。
- **导入约定**（源自 CLAUDE.md）：包内用相对导入（如 `from .user import ...`）；跨模块用相对 `backend/app` 的绝对导入（如 `from config.db import ...`、`from api.v1 import ...`）。
- `__init__.py` 统一从 `model` / `schemas` 导出领域对象，供路由层消费。

### 2.3 演进方向

1. **业务下沉**：把路由内的 ORM 操作迁移到 service 层，数据访问迁移到 repository 层，使路由层只负责参数绑定与响应组装。
2. **响应模型化**：目前接口直接返回裸 dict，无 `response_model`，演进时可引入 Pydantic 响应模型统一出参契约。
3. **`utils/verify_user.py` 独立为通用鉴权依赖**：目前 `user.py` 与 `verify_user.py` 各自实例化了一个 `HTTPBearer()`，演进时可统一为单一鉴权依赖供全路由复用。

## 3. 数据层

### 3.1 异步引擎与会话工厂

文件：`backend/app/config/db.py`

```python
async_engine = create_async_engine(
    ASYNC_DATABASE_URL,
    echo=True,              # 打印 SQL 日志（生产建议关闭）
    pool_size=10,
    max_overflow=20,
    pool_recycle=3600,      # 连接 1 小时回收，规避 MySQL wait_timeout
    pool_timeout=30,
    pool_pre_ping=True,     # 执行前 ping，剔除死连接
)

AsyncSessionLocal = async_sessionmaker(
    bind=async_engine,
    class_=AsyncSession,
    expire_on_commit=False,  # commit 后对象属性仍可访问
)

Base = declarative_base()
```

要点：

- 连接串 `ASYNC_DATABASE_URL` 从环境变量读取（见 [config/security.py](#7-配置管理env)），不再是硬编码的 `root@localhost:3306/web1`——CLAUDE.md 中「连接串硬编码」的描述已过时。
- 引擎是**惰性**的：启动应用不建立数据库连接，首个请求才真正建连。因此 MySQL 未启动时应用可启动，但涉及 DB 的接口会报错。
- `echo=True` 会向终端输出全部 SQL，生产环境应关闭。

### 3.2 get_db 依赖

`get_db()` 是标准的 **yield 依赖**，通过 `db: AsyncSession = Depends(get_db)` 注入到每个端点：

```python
async def get_db():
    async with AsyncSessionLocal() as session:
        try:
            yield session
            await session.commit()      # 正常路径自动提交
        except Exception as e:
            await session.rollback()    # 异常回滚并重新抛出
            raise e
        finally:
            await session.close()       # 关闭会话（归还连接）
```

事务边界即请求边界：端点内部无需手动 `commit`（路由里仍有部分显式 `commit`，属于冗余但无害），异常时自动回滚，保证数据一致性。

### 3.3 ORM 模型

文件：`backend/app/model/user.py`，表名 `user`：

| 字段 | 类型 | 约束 / 说明 |
| --- | --- | --- |
| id | Integer | 主键，自增 |
| username | String(50) | 唯一、非空、有索引 |
| email | String(100) | 唯一、非空、有索引 |
| password_hash | String(255) | 非空，存 argon2 哈希 |
| avatar | String(255) | 头像 URL，可选 |
| bio | Text | 个人简介，可选 |
| status | SmallInteger | 默认 1（0-禁用 1-正常） |
| is_admin | SmallInteger | 默认 0 |
| created_at | DateTime | `server_default=func.now()` |
| updated_at | DateTime | `server_default=func.now()`，`onupdate` 自动刷新 |

> 说明：模型使用 `declarative_base()` 的经典 `Column` 风格，未采用 SQLAlchemy 2.0 的 `Mapped`/`mapped_column` 类型化写法；字段类型上 `datetime` 等属于语义宽松用法，演进时可改为类型化映射。

### 3.4 无 Alembic 迁移的说明

- 项目**未接入 Alembic**，且代码中**没有任何 `create_all` 调用**。因此 `user` 表不会自动创建。
- 首次部署需**手动建表**（如在 MySQL 中执行与 `model/user.py` 字段定义一致的建表 SQL，或用临时脚本触发建表）。
- 存在字段与代码不同步的风险：手动建表 + 无迁移 = 结构漂移只能靠人眼比对。
- 改进方向见[第 11 节](#11-未来改进方向)。

## 4. 认证与安全

### 4.1 JWT（HS256）

文件：`backend/app/config/security.py`

- `ALGORITHM = "HS256"` 硬编码。
- `SECRET_KEY` 通过环境变量 `SECRET_KEY` 注入（缺失时 `SECRET_KEY = None`，此时 `jwt.encode/decode` 将失败——见[已知注意事项](#10-已知注意事项)）。
- **当前 Token 不携带 `exp` / `iat` 过期时间**，即签发的 Token 永不过期，直到 `SECRET_KEY` 轮换。`security.py` 中有一行被注释的 `ACCESS_TOKEN_EXPIRE_MINUTES`，提示作者原计划加入有效期。
- 签发（`api/v1/user.py` 登录）：

```python
token = jwt.encode(
    {"sub": str(user.id), "username": user.username},
    SECRET_KEY,
    algorithm=ALGORITHM,
)
```

`sub` 存字符串形式的用户 ID（JWT 规范要求 `sub` 为字符串）。

### 4.2 密码哈希（argon2）

- 使用 `passlib` 的 `CryptContext(schemes=["argon2"], deprecated="auto")`，底层为 `argon2-cffi`（当前密码学推荐算法，抗 GPU 暴力破解）。
- 注册时 `pwd_context.hash(data.password)` 生成哈希存入 `password_hash`；登录时 `pwd_context.verify(data.password, user.password_hash)` 校验。

### 4.3 鉴权依赖 verify_login

文件：`backend/app/utils/verify_user.py`

```python
security = HTTPBearer()  # 自动从 Authorization 头取出 Bearer Token

def verify_login(credentials: HTTPAuthorizationCredentials) -> int:
    """验证 token 并返回用户 id"""
    payload = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
    user_id = int(payload["sub"])
    return user_id
```

- 通过 `credentials: HTTPAuthorizationCredentials = Depends(security)` 注入。
- 解码失败抛出 `HTTPException(401, "token无效")`。
- 注意：`verify_user.py` 与 `api/v1/user.py` **各自**实例化了一个 `HTTPBearer()`；且 `verify_login` 内有一行 `print("TOKEN:", token)` **调试打印，会把 Token 明文打进日志**，应移除（见[已知注意事项](#10-已知注意事项)）。

### 4.4 注册流程

端点：`POST /api/v1/user/register`

```
body: Account{username, password, email, avatar?, bio?}   query: code（邮箱验证码）
```

1. 用 `or_(username == ..., email == ...)` 查重，已存在则 `400 用户名或邮箱已存在`。
2. `verify_email_code(email, code)` 校验验证码，失败则 `400 验证码不正确或已过期`（验证码一次性，校验成功即删除）。
3. `pwd_context.hash(password)` 哈希。
4. 写入 `User`（username / password_hash / email / bio / avatar），`commit` + `refresh`。
5. 返回 `{id, username, email, bio, avatar}`。

### 4.5 登录流程

端点：`POST /api/v1/user/login`

```
body: LoginRequest{username, password}
```

1. 按 `username` 查用户。
2. 用户不存在或 `pwd_context.verify` 失败 → 统一返回 `401 用户名或密码不正确`（不区分「用户不存在」与「密码错误」，防止用户名枚举）。
3. 签发 JWT（`sub` + `username`）。
4. 返回 `{id, username, access_token}`。

### 4.6 更新 / 删除用户

- `PUT /api/v1/user/update`（Bearer 鉴权）：
  - `verify_login` 解析用户 ID → 加载用户。
  - 更新 `username` / `email` 前做**排除自身**的唯一性校验（`User.id != user_id`）。
  - `bio` / `avatar` 仅在非 `None` 时更新（Pydantic 缺省 `None`，语义为「未传则不修改」）。
  - `password` 传入则重新哈希。
  - 提交后调用 `await update_version()` 触发缓存版本号自增（见[第 5 节](#5-缓存层)）。
- `DELETE /api/v1/user/delete`（Bearer 鉴权）：物理删除当前用户，提交后同样调用 `update_version()`。
- 二者均返回中文 `msg` 提示。

> 设计注意：更新接口复用了 `Account` 模型，而 `Account.password` 是必填字段（`min_length=6`，无默认值），因此**更新时必须同时提交密码**，尽管代码逻辑中密码是可选的。语义与模型存在不一致，见[已知注意事项](#10-已知注意事项)。

### 4.7 安全注意事项

- **CORS 配置有隐患**：`main.py` 中 `allow_origins=["*"]` 与 `allow_credentials=True` 同时开启。按浏览器规范，`*` 通配源不能与 `credentials` 共存，且等于允许任意站点携带凭证访问，生产环境必须改为显式白名单。
- **Token 无过期时间**，泄露后无法自然失效。
- `verify_login` 中残留 `print("TOKEN: ...")` 会泄露 Token 到控制台日志。
- `.env` 文件包含真实密钥，需确认已加入 `.gitignore`，避免入库。

## 5. 缓存层

文件：`backend/app/config/cache.py`

### 5.1 Redis 客户端

```python
redis_client = redis.Redis(
    host="localhost",
    port=6379,
    db=0,
    password=None,            # Redis 密码（当前无）
    decode_responses=True,    # 自动解码为字符串
    encoding="utf-8",
    max_connections=20,       # 连接池上限
    socket_connect_timeout=5,
    socket_timeout=5,
    health_check_interval=30,
)
```

- 使用 `redis.asyncio`，**惰性连接**：仅实例化客户端，不阻塞应用启动；首个操作时建立连接。
- 地址 / 密码目前仍是硬编码的本地配置（`localhost:6379`），未走环境变量。

### 5.2 缓存工具函数

| 函数 | 作用 |
| --- | --- |
| `get_cache_key(prefix, *args, version=None, **kwargs)` | 拼接确定性缓存键，形如 `prefix:v3:arg1:k=v`（kwargs 按 key 排序，保证顺序稳定） |
| `get_from_cache(key)` | 取 JSON 反序列化结果，无则 `None` |
| `set_to_cache(key, value, expire=300)` | `setex` 写 JSON（`json.dumps(..., default=str)`，可序列化 datetime 等） |
| `delete_cache(key)` | 删单键 |
| `delete_cache_pattern(pattern)` | `scan_iter` 模糊删除匹配键 |
| `get_search_version()` | 读取 `search_version` 计数器 |
| `update_version()` | `incr` 自增 `search_version` |

### 5.3 版本化缓存失效模式

项目预置了一套「**缓存键内嵌版本号 + 数据变更时自增版本**」的失效模式：

1. 写入缓存时把版本号拼进 key（`get_cache_key(..., version=v)`），新版本与旧版本天然是不同 key。
2. 用户数据发生变更（更新 / 删除用户）时调用 `update_version()` 使 `search_version` 自增。
3. 查询方用 `get_search_version()` 拿到最新版本号拼 key，读到的自然是新数据；旧版本 key 可配合 `delete_cache_pattern` 定期清理。

当前仓库中 `user.py` 已调用 `update_version()`，但**尚不存在读取该版本的搜索 / 列表接口**，该模式为后续「用户搜索 / 列表」等高频查询预留。注意：目前版本号全局唯一，所有数据变更共享同一计数器，粒度较粗。

## 6. 邮箱验证码模块

文件：`backend/app/utils/email.py`、`backend/app/api/v1/email.py`

### 6.1 发送流程

端点 `POST /api/v1/email/send`（body 为 `EmailStr`）→ `send_email(email)`：

1. 生成 6 位数字验证码（`random.randint(100000, 999999)`）。
2. 写入 Redis：key 为 `email_code:{email}`（经 `get_cache_key("email_code", email)`），TTL **300 秒**（5 分钟）。
3. 调用 Resend SDK 发送邮件（`from` 固定为 `fishmo <noboard@fishmo.top>`）。
   - **关键实现**：Resend SDK 是同步实现（内部走 `requests`），代码用 `await asyncio.to_thread(resend.Emails.send, params)` 丢进线程池，避免阻塞事件循环。
4. 发送失败时删除已写入的验证码并返回 `500 发送验证码失败: ...`。

### 6.2 校验流程

`verify_email_code(email, code)`：

- 读取 `email_code:{email}`，比对一致则**删除该键并返回 True**（一次性验证码，防重放）。
- 不存在或不匹配返回 False。
- 另有 `clear_email(email)` 供手动清除验证码。

### 6.3 API 端点

`POST /api/v1/email/send`：请求体 `{"email": "xxx@example.com"}`，成功返回 `{"message": "验证码已发送，请检查你的邮箱。"}`。

## 7. 配置管理（.env）

文件：`backend/app/config/security.py`、`backend/app/.env`

```python
from dotenv import load_dotenv
load_dotenv()  # 从 .env 加载环境变量

SECRET_KEY = os.getenv("SECRET_KEY")
ALGORITHM = "HS256"
RESEND_API_KEY = os.getenv("RESEND_API_KEY")
ASYNC_DATABASE_URL = os.getenv("ASYNC_DATABASE_URL")
```

- 应用启动目录为 `backend/app`，`.env` 位于同目录，`load_dotenv()` 默认读取 CWD 下的 `.env`。
- 必须配置的环境变量：
  - `SECRET_KEY` — JWT 签名密钥（缺失会导致登录 / 鉴权直接失败）。
  - `RESEND_API_KEY` — Resend 邮件密钥（缺失时发送验证码会失败）。
  - `ASYNC_DATABASE_URL` — 异步 MySQL 连接串（如 `mysql+aiomysql://user:pass@localhost:3306/web1`，缺失时引擎创建即报错）。
- 被注释的 `ACCESS_TOKEN_EXPIRE_MINUTES` 提示未来 Token 有效期会走环境变量。
- `db.py` / `cache.py` 仍残留硬编码（如 Redis 地址），生产需收敛到配置层。

## 10. 已知注意事项

1. **【阻断级】`config/db.py` 的绝对导入在冷启动时必然失败**
   `config/db.py` 第 3 行使用 `from security import ASYNC_DATABASE_URL`，但：
   - 不存在顶层模块 `security`（只有 `config/security.py`）；
   - `config/__init__.py` 先导入 `.db`、后导入 `.security`，导致连 `sys.modules` 的巧合路径都不存在。

   实际验证结果：
   ```
   from config.db import get_db
   → ModuleNotFoundError: No module named 'security'
   ```
   **当前应用无法启动。** 修复方式（任选其一，推荐前者）：
   ```python
   # config/db.py
   from config.security import ASYNC_DATABASE_URL   # 改为相对 backend/app 的绝对导入
   # 或包内相对导入
   from .security import ASYNC_DATABASE_URL
   ```

2. **`resend` 未写入 `requirements.txt`**：`utils/email.py` 依赖 `resend`，当前 venv 中已安装 2.35.0，但依赖清单中缺失，新环境按 requirements 安装后邮件功能会 `ImportError`。需将 `resend` 版本补入依赖文件。

3. **CLAUDE.md 部分描述已过时**：数据库连接串已从硬编码改为环境变量（`ASYNC_DATABASE_URL`）；`utils/` 不再是空目录（新增 `email.py` / `verify_user.py`）；`api/v1` 新增 `email_router`。

4. **JWT 无过期时间**：签发的 Token 永久有效（`exp` 未设置），安全上建议补上有效期并支持刷新。

5. **CORS 配置**：`allow_origins=["*"]` + `allow_credentials=True` 组合不符合浏览器规范且存在安全风险，生产必须改为域名白名单。

6. **`verify_login` 残留调试打印**：`print("TOKEN:", token)` 会把明文 Token 输出到日志，应删除。

7. **更新接口复用 `Account` 模型**导致密码变为必填（`min_length=6` 无默认值），与代码中「可选更新」的语义不符；且注册 / 更新共用一套校验，无法区分场景。

8. **无数据库迁移**：没有 Alembic、也没有 `create_all`，`user` 表需手动创建，存在结构漂移风险。

9. **`SECRET_KEY` 缺失时无显式兜底**：`SECRET_KEY = os.getenv("SECRET_KEY")` 未提供开发默认值，缺失会让 JWT 相关接口全部失败，且报错信息不直观（建议加本地默认值或启动时校验并提示）。

10. **无请求级日志 / 可观测性**：全程只有 `print`，无结构化日志、无请求 ID、未接 Sentry/OpenTelemetry（`sentry-sdk` 已出现在依赖中但未被使用）。

11. **`api/` 为命名空间包**（无 `__init__.py`），功能正常，但与其余包风格不统一，建议补 `__init__.py`。

12. **版本化缓存粒度较粗**：`search_version` 为全局唯一计数器，任何用户变更都会使所有缓存失效，且目前并无消费该版本的接口（`update_version()` 的调用是未来功能的铺垫）。
